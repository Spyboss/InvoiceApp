## current step

step 7 (import + parallel run) is **in progress**. the software half is shipped; the acceptance is half met — imported totals match the csv source exactly, but the month of parallel running is a real month of the business's paper and cannot be a test. what shipped:

- `/import`: two files, `invoices.csv` from the old app and the yard sheet. a good upload redirects to `/import?run=<id>` and the page reads the run back from the database. `import.run` is OWNER only.
- the import is one transaction and all or nothing: a file with one bad row is refused whole, every problem named on its line, and nothing is written. a second upload of the same file finds every number already held and writes nothing, so the same file is safe to send every day of the month.
- imported papers keep the number the old app printed (`documents.imported_at`, `documents.import_run_id`) and are never renumbered; the app's counters are lifted above every imported number for the year afterwards, with the two sales series lifted together because they split one legacy series (D09/D21 unchanged, D23).
- a `SALES` row with nothing owing is a cash invoice and one with a balance is a leasing sale; stock follows the paper (sale: `RECEIVE`+`SELL`, advance: `RECEIVE`+`RESERVED`, proforma: `RECEIVE` only). customers match on nic then name, units on chassis, so five years of paper does not become five hundred copies of the same person.
- the acceptance is a database constraint, not a screen: `import_runs` stores what the file claimed and what the database held, and `check (source_totals = stored_totals)` refuses a run that does not balance. `import_run_id` is a deferred foreign key because the papers are written before the run row, inside the one transaction.
- `/reconciliation`: upload the same file for a range of days and the store compares it with the papers that came in from a file, per day and per document type, keeping papers, price, down and balance apart. the difference and `matched` are generated columns, so a line cannot claim a match; a run that finds a difference writes a `RECONCILIATION` alert in the same transaction. `reconcile.run` is OWNER, MANAGER and ACCOUNTS.
- the two upload pages needed csrf middleware that reads multipart bodies; it now does, behind `http.MaxBytesReader` at 10 MB, and every upload is hashed with sha256 and stored with its run. `docs/IMPORT-FILES.md` is the column reference for both files and for the daily routine of the parallel month.

step 7 acceptance so far: covered by tests — an upload writes the book and a repeat writes nothing; a file that does not add up is refused whole and the typed make kept; an upload with no csrf token is a 403; a salesperson gets 403 on both pages and accounts gets 403 on `/import`; a reconciliation that agrees records `matched`, one that drifts records the difference and raises an alert; bad dates are refused. the remaining half is one month of the business's own paper, reconciled daily, which is an action at the counter rather than a commit — so this step stays `in progress` until that month is real.

step 7 also carried the interface pass (D24). all fifteen screens were rewritten against one frame and one voice: `Layout` now holds the dealership, the destinations, who is signed in and the sign-out form, so no page repeats them; taglines under headings, helper text under inputs and paragraphs explaining rules in advance are gone, and a constraint that mattered folded into its label ("Password (12 characters or more)"); facts are `dl.facts` rows or tables with headings; empty states are one line and say "none yet" differently from "no match"; the alert channels read as a fact ("this page only") rather than a warning. view fields no template drew were deleted rather than kept (home's `CanSeeAudit`, the alert's `Kind`, the import page's `Attempted`/`Notice`, the reports' `ReadAll`, a document's `IsQuote`), and the settings screen shows a read-only `dl.facts` view to anyone without `settings.write` instead of a disabled form. every page was measured at 360px: nothing scrolls sideways, and the wide tables scroll inside their own box with the cell padding gave up first. the stylesheet is now revalidated with an `ETag` and `no-cache` (D25) after a css rule was found to be serving from a browser cache.

step 6, for the record: `/settings` and `/users` are the owner's screens (company details, discount percent, variance threshold, backdate limit, alert email and telegram chat; list everyone, change a role, activate or deactivate, reset a password), each refusing anyone without the permission before it loads. a `users_keep_one_owner` trigger refuses removing the last active owner, and MANAGER no longer carries implicit `user.manage`. approval pins re-authenticate the approver's own password and check the effective `document.approve` permission, so a clerk cannot forge a sign-off. a void keeps the paper and its number, returns the unit to the yard, and writes an alert; alerts fire on void, variance and numbering gap, are insert-only, and leave by email and/or telegram when configured.

step 5, for the record: a receipt pays one named invoice and can never exceed what it still owes, in the store and in a database trigger. a receipt is inserted once; handing money back is a reversal dated the day it happens, so a counted day is never rewritten. money cannot be dated on a closed day, and a close is insert only, so a z cannot be edited by anyone. the z stores its totals and its lines as they were at close time, and exports as csv.

step 4, for the record: `/documents` issues quotations, cash and leasing invoices, advance receipts and proformas. numbers come from `document_series`, bumped in the same transaction as the document, so concurrent clerks never share one and a rollback leaves no gap. a sale sets the unit sold and writes the `SELL` movement in that transaction; a quotation converts once. printed fields are frozen by a database trigger, and the first pdf is archived with its sha256, so later downloads serve the same bytes. the proforma was compared against a libreoffice render of `BIBILE 01.docx`: the table and body agree within about 1pt.
